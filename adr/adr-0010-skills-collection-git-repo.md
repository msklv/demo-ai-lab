# ADR-0010: Каталог агентских скиллов — отдельный публичный git-репозиторий `skills-demo-ai-lab`

- Дата: 2026-11-10
- Статус: Accepted
- Ревизия: 2026-11-10 — добавлен второй апстрим (`ClickHouse/agent-skills`, 11 скиллов): каталог
  стал многоапстримным, пины и исключения вынесены в `upstreams.tsv`, сводная атрибуция — `notices/`
- Ревизия: 2026-11-10 — апстрим `yc-software/qm` снят по решению владельца (стоковые скиллы платформы
  в каталоге не остаются); в гейте сохранён белый список открытых лицензий; правило «только публичные
  апстримы целиком, никаких локальных адаптаций» в силе. Каталог — 29 скиллов, два апстрима
- Ревизия: 2026-11-10 — добавлен третий апстрим `NousResearch/hermes-agent` (MIT, 1 скилл
  `popular-web-designs` — 54 дизайн-системы, датасет из `VoltAgent/awesome-design-md`): каталог 30 скиллов.
  Правило импорта уточнено: берём у того, кто сохранил атрибуцию первоисточника, а не у переупаковщика
- Ревизия: 2026-11-10 — `obra/superpowers` (MIT, 15 скиллов процесса разработки) и три отдельных
  MIT-скилла из своих первоисточников: `Cocoon-AI/architecture-diagram-generator`,
  `blader/humanizer` (лицензия внутри скилла главнее репозиторной), `excalidraw` из
  `NousResearch/hermes-agent`. Каталог — 48 скиллов

## Контекст

Шагу 2 демо нужен **каталог скиллов** — готовых процедур в формате SKILL.md, которые агент
подхватывает по описанию и применяет сам (проверка PDF, сборка презентации, дизайн-гайд,
MCP-сервер, тесты веб-приложения). Сейчас такого набора у стенда нет: скиллы живут в профиле
агента на Mac, в кластер и на показ не переносятся, каталога как артефакта не существует.

Первым вариантом был **self-host реестра SkillHub** (`iflytek/skillhub` v0.2.26): 4 пода
(server, web, PostgreSQL, Redis), SSO-клиент Keycloak `skh`, адрес `skh.demo-ai-lab.ru`,
приёмка T1–T8 — спека architecture/specs/skills-registry-spec.md v1.0. Спека **снята
2026-11-10** по двум причинам:

- **Цена не соответствует предмету показа.** Что демонстрируется — сам скилл и то, что агент
  применяет его без человека; витрина с RBAC, ревью и аудитом публикации для этого не нужна,
  а платим мы PG + Redis + SSO-клиент + 4 пода + обслуживание.
- **Контракт спеки расходился с апстримом.** При разборе против кода v0.2.26 выяснилось, что
  часть заявленного в спеке не работала бы как записано: хранилище пакетов без
  `STORAGE_BASE_PATH` уходит в `/tmp/skillhub-storage` (PVC остаётся пустым), env-имена
  политики допуска не соответствуют `@ConfigurationProperties(prefix = "skillhub.access-policy")`,
  `/api/v1/auth/me` отдаёт `oauthProvider`/`platformRoles`, а не `provider`/`roles`, сессии — в
  Redis, а не в PG (риск R-T2 утверждал обратное). Это лечится правками спеки, но сам вопрос
  «нужен ли реестр» от этого не меняется.

Готовый источник скиллов — публичный репозиторий `anthropics/skills` (19 каталогов; 18 из них
под Apache-2.0, `doc-coauthoring` — без файла лицензии). Часть скиллов применима на стенде
напрямую (документы, дизайн, MCP, тесты), часть — как примеры качества процедур.

## Решение

Каталог скиллов — **отдельный публичный git-репозиторий** [`msklv/skills-demo-ai-lab`](https://github.com/msklv/skills-demo-ai-lab)
(создан 2026-11-10). Никакого сервера, БД и SSO для каталога не заводим.

Структура:

```
skills-demo-ai-lab/
├── skills/<имя-скилла>/       # один каталог = один скилл: SKILL.md + ассеты + его LICENSE.txt
├── upstreams.tsv              # апстримы: repo, пин-коммит, каталог скиллов, notices, исключения
├── scripts/sync-upstream.sh   # переимпорт всех апстримов по пинам
├── scripts/check-catalog.py   # гейт: SKILL.md/description/LICENSE, пины, сверка README с фактом
├── UPSTREAM.md                # что и на каком коммите импортировано; что исключено и почему
├── NOTICE                     # атрибуция апстримов (© Anthropic PBC, © ClickHouse Inc.), шрифты
├── notices/                   # дословные notices апстримов (THIRD_PARTY_NOTICES, NOTICE)
└── LICENSE                    # Apache-2.0 — обвязка репозитория
```

Правила, которые держат каталог каталогом:

| Правило | Почему |
|---|---|
| Скилл = один каталог `skills/<name>/`, в нём SKILL.md с frontmatter `name` + `description`, имя каталога = `name` | по `name`/`description` агент находит скилл; расхождение имён ломает адресацию и установку |
| У каждого скилла есть `LICENSE.txt` | публичный каталог: скилл без заявленной лицензии не публикуется (так исключён `doc-coauthoring`) |
| Ассеты — внутри каталога скилла, общих папок нет | установка одного скилла не должна тянуть чужие файлы |
| Импортированные скиллы не правятся; свои — отдельными каталогами | иначе следующий re-import конфликтует с локальными правками |
| Приватного в каталоге нет (пароли, токены, внутренние адреса, ПДн) | репозиторий публичный — те же правила, что в `msklv/demo-ai-lab` (AGENTS.md) |
| **Только открытые лицензии**; лицензия распознаётся гейтом по белому списку (Apache-2.0, MIT, BSD-2/3, ISC, MPL-2.0, OFL-1.1, CC0, CC-BY-4.0, Unlicense) | «открытая» на глаз не считается: элемент с неизвестной/проприетарной лицензией — красный гейт, а не решение по случаю |
| Каталог = **публичные апстримы целиком**, локальных адаптаций нет | правка под контур (внутренние адреса, корпоративные интеграции, зеркала) превращает публичный каталог в утечку; такие скиллы живут отдельным приватным каталогом |
| README.md перечисляет все скиллы и их источник; гейт сверяет таблицу с содержимым `skills/` и пины апстримов | индекс не отстаёт от факта (проверка — `scripts/check-catalog.py`) |

Импорт апстримов (перечень и пины — `upstreams.tsv`, по строке на апстрим; всего 29 скиллов, ≈14 МБ):

- **`anthropics/skills`** — пин `2c5958ecac7cee2b583967a2c4981d0f4a75c579` (2026-11-06), 18 скиллов;
  каталоги `spec/`, `template/`, `.claude-plugin/` не импортируются (это не скиллы);
- **`ClickHouse/agent-skills`** — пин `d3b2b5ba43a8b80c2d08858b68d53edc701b5ace` (2026-11-02),
  11 скиллов (chdb-*, clickhouse-*, clickstack, infra-*); `packages/` не импортируется — это
  сборочные скрипты апстрима, а не скилл;
- атрибуция переупакованного: `popular-web-designs` содержательно принадлежит
  `VoltAgent/awesome-design-md`, и импортируется форма с прямым указанием источника во frontmatter
  (в коллекциях-агрегаторах такая атрибуция часто вычищена — брать там, где она сохранена);
- **`NousResearch/hermes-agent`** — пин `b3746e35ddd32079697728e2df57a9d78f1e9e32` (2026-11-10),
  один каталог `skills/creative/popular-web-designs`; остальные каталоги `skills/creative` не берём —
  там дубли скиллов Anthropic, уже приезжающих из своего апстрима;
- лицензия одна на репозиторий (ClickHouse, hermes-agent) → корневой LICENSE копируется в каталог
  каждого скилла: отдельно установленный скилл приезжает вместе с лицензией (Apache-2.0 п. 4, MIT —
  текст и копирайт);
- лицензии: `LICENSE.txt` в апстриме встречается в трёх вариантах текста — все три Apache-2.0
  (различается только appendix/строка копирайта), ограничительных дополнений нет; файлы
  копируются дословно; шрифты `canvas-design/canvas-fonts` — SIL OFL 1.1 (`*-OFL.txt` рядом);
- исключён `doc-coauthoring`: файла лицензии нет, права на перераспространение не заявлены;
- обновление пина — правка строки в `upstreams.tsv` + `scripts/sync-upstream.sh [repo]`
  (`UPSTREAM_REF=<sha>` — пробный ref) и гейт `check-catalog.py`; новый апстрим = строка в
  `upstreams.tsv`, прогон скрипта и таблицы в UPSTREAM.md/NOTICE.

Потребление:

```bash
git clone https://github.com/msklv/skills-demo-ai-lab.git ~/git/skills-demo-ai-lab
cp -R ~/git/skills-demo-ai-lab/skills/docx "$HERMES_HOME/skills/"   # Hermes
+# прочие клиенты формата SKILL.md — копия каталога в их skills/, конверсия не нужна
```

Стенд: адрес `skh.demo-ai-lab.ru`, ns `skillhub`, PostgreSQL/Redis, клиент Keycloak `skh`,
`gitops/infra-apps/skillhub/` и `scripts/skillhub_secrets.sh` — **не заводятся**; спека
architecture/specs/skills-registry-spec.md удалена, строка адреса из architecture/endpoints.md
снята.

## Последствия

- Инфраструктуры под каталог нет вовсе: доступность = доступность GitHub, состояние = git,
  версия скилла = коммит, откат = `git revert`.
- Каталог переиспользуем вне стенда (агент на Mac, CI, другие стенды) и не тянет за собой
  доки стенда; 12 МБ бинарей (шрифты, OOXML-схемы) не лежат в репозитории инфраструктуры.
- Лицензии третьих сторон изолированы в своём репозитории и не смешиваются с Apache/CC
  содержимым `demo-ai-lab`.
- Цена, которую принимаем: **нет витрины с поиском и UI** (навигация — README + `git ls-files`),
  **нет RBAC и аудита публикации** (запись = push в `main`, авторство — git, ревью — PR),
  установка в агента — копирование каталога (обновление = `git pull` + повторная копия),
  пин апстрима обновляется вручную и осознанно.
- Демо показывает «скилл как артефакт»: взять скилл из каталога → агент применяет процедуру.
  Витрина реестра и публикация через UI из сценария уходят.
- Каталог закрывает потребность «нужен публичный вариант скилла»: если в контуре скилл адаптирован
  (свои адреса, свои интеграции), публичная версия берётся здесь как исходник, а адаптация остаётся
  в приватном каталоге контура — в публичный репозиторий она не уезжает.
- Если понадобится закрытый набор (внутренние скиллы с приватными адресами) — это отдельный
  приватный репозиторий по той же структуре и тот же гейт; в публичный каталог он не попадает.
- Приватные/внутренние скиллы стенда (`demo-ai-lab-stand`, `homelab-*`) остаются в профиле
  агента: публичный каталог их не содержит (в них LAN-адреса и внутренние процедуры).

## Альтернативы (рассмотрены и отклонены)

- **Self-host реестра SkillHub v0.2.26** (спека v1.0, снята): витрина, RBAC, версии, поиск —
  ценой 4 подов, PG + Redis, SSO-клиента и обслуживания; для показа «агент применяет скилл»
  избыточно, а расхождения контракта спеки с апстримом добавили бы дни на отладку.
- **MCP Registry как каталог скиллов**: другой предмет — реестр MCP-*серверов* (`mcp.`, ADR-0005);
  скилл — не MCP-сервер, модель публикации (доменный токен) и формат пакета не совпадают.
- **Форк `anthropics/skills`**: своя история поверх чужой, лицензионные варианты апстрима и наши
  скиллы в одном дереве, обновление апстрима = merge-конфликты вместо копирования по пину.
- **Каталог внутри `demo-ai-lab`**: другой цикл жизни (контент меняется чаще инфраструктуры),
  вес бинарей в репо доков, и публичность каталога ≠ публичность архитектурных доков.
- **OCI-артефакты в реестре образов**: скилл — набор файлов и инструкций, а не образ; появился
  бы лишний слой (push/pull артефакта) и зависимость от реестра, ничего не давая агенту.
