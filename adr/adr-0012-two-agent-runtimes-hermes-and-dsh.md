# ADR-0012: Два агентских рантайма на демо — Hermes Agent и DeepSeek Harness (`dsh`), оба за SSO

- Дата: 2026-11-17
- Статус: Accepted (решение владельца 2026-11-17: «на демо показываем двух агентов — Hermes Agent и
  dsh, оба с авторизацией через SSO»). `dsh` **не развёрнут**: спека и деплой — шаг 4.
- Заменяет: план шага 4 в части «мультипользовательский агентный рантайм» — прежняя спека снята из
  репозитория тем же проходом (история — в git до 2026-11-17).
- Связанные: ADR-0004 (внешний доступ, LAN-first), ADR-0005 (MCP), ADR-0007 (модели и бюджет VRAM),
  ADR-0008 (внешний LLM только через `llm-svc.`), `architecture/specs/hermes-spec.md` (H\*),
  `architecture/endpoints.md`
- Проверено по источникам 2026-11-17: `github.com/deepseek-ai/deepseek-harness` (README, `docs/`,
  LICENSE MIT, публичный preview), `deepseek.com/harness`, гайды `guide/public-deployments` и
  `user-guide/configuration`; факты Hermes — `hermes-spec` §0 (замеры стенда 2026-11-06).

## Контекст

| Что | Факт (2026-11-17) |
|---|---|
| Сцена шага 4 | агент — не «чат побольше», а цикл «решил → вызвал инструмент → посмотрел → решил снова»; показывать надо и цикл, и ограничения рантайма |
| Hermes Agent | развёрнут: `hm.`, ns `her`, под 1/1, панель за SSO (**public + PKCE**, клиент `hm`), MCP `doc.`/`ysrch.`, `deepseek-flash` через `llm-svc.` + локальная 27B через `api.` |
| DeepSeek Harness (`dsh`) | MIT, архитектура «everything is a plugin» (Cordis); профиль `web` слушает loopback `:3080`, внешний вход отдан реверс-прокси (`--public-url`, `--trusted-host`); **нативного OIDC нет** — вход по launch-token и подписанной cookie, учётка одна (уровень прав — владелец процесса) |
| Требование | оба агента — за одним SSO Keycloak (`auth.demo-ai-lab.ru`, realm `dev`) |

## Решение

| Что | Решение |
|---|---|
| Состав | **два рантайма**: `hm.` — Hermes Agent, `dsh.` — DeepSeek Harness; на сцене оба |
| Роли на демо | Hermes — платформа: MCP-инструменты каталога, маршрутизация моделей (внешняя/локальная); dsh — харнесс: песочница с пресетами permissions (`read-only` / `workspace-write` / `danger-full-access`) и плагинная расширяемость |
| Авторизация Hermes | **нативная**: `dashboard_auth/self_hosted`, OIDC public + PKCE S256, клиент `hm` (работает с 2026-11-06) |
| Авторизация dsh | **на шлюзе**: маршрут `dsh.` в Higress за OIDC-гейтом Keycloak (клиент `dsh`); сам dsh никого не аутентифицирует |
| Публикация `dsh.` | наружу — только после приёмки гейта, до неё — LAN; порт слушателя не публикуется и доступен только из шлюза |
| Инструменты | MCP-серверы стенда — **один общий набор для обоих агентов** (список и адреса — ниже) |
| Модели | `deepseek-flash` через `llm-svc.` (DLP + страж, ADR-0008) и `Qwen3.8-27B-UD` через `api.` (ADR-0007) |
| Размещение | `her` — пара k8s-02/03 (как сейчас); `dsh` — k8s-01 или k8s-05, не на GPU-ноде; бюджет — §5 `architecture/ARCHITECTURE.md` |
| Механика | образ и пин, каталог `gitops/apps/dsh/` (Argo CD), параметры гейта, режим песочницы, приёмка — спека `architecture/specs/dsh-spec.md` (пишется отдельно, буква фаз — не занятая) |

## MCP-серверы стенда

Правило одно: **MCP-серверы смотрят только внутрь** — внешних адресов нет, вызовы из подов агентов по in-cluster DNS; набор инструментов **общий** для Hermes и dsh.

| Сервер | ns | Внутренний адрес | Каталог `mcp.` |
|---|---|---|---|
| Docling MCP | `doc` | `http://docling.doc.svc:8000/mcp` | `ru.demo-ai-lab/docling@1.0.0` |
| Yandex Search MCP | `ysrch` | `http://yandex-search.ysrch.svc:8766/mcp` | `ru.demo-ai-lab/yandex-search@1.0.0` |
| Kuvasz MCP | `monitoring` | `http://kuvasz.monitoring.svc:8080/mcp` | `ru.demo-ai-lab/kuvasz@1.0.0` |
| GitHub MCP | `mcp-github` | `http://github-mcp.mcp-github.svc:8101/mcp` | обязан (сейчас вне каталога) |
| Firecrawl MCP (план, C6) | `fc` | внутрикластерный, при реализации | обязан после реализации |

Правила:
- ни один MCP не публикуется снаружи — ни через edge, ни путём Ingress'а, ни в LAN;
- каждый MCP-сервер попадает в каталог `mcp.`; запись ссылается на внутренний адрес;
- ключи инструментов (Yandex Search, Kuvasz `X-API-KEY`, GitHub PAT per-request) — в Secret потребителя, не в каталоге.

**Следствия — ещё не внедрено:** у `doc.` снимается путь `/mcp` (конвертация на `/` остаётся публичной),
`ysrch.` закрывается снаружи целиком, `mon./mcp` работает только из кластера; GitHub MCP получает адрес
в каталоге. К правке: `architecture/endpoints.md`, Ingress'ы `doc`/`ysrch`, `architecture/specs/mcp-registry-spec.md`.

## Последствия

- Сцена показывает два класса рантайма под одним IdP — тезис «агент ограничен политикой, а не доверием» подтверждается на обоих.
- `dsh` без внешнего гейта равен «шелл по HTTP» с правами владельца: SSO — условие публикации, а не улучшение.
- Мультипользовательский вход у dsh не заявляется: на сцене это личный харнесс, вход — один.
- GitHub MCP доступен обоим агентам и обязан быть в каталоге; токен — per-request из Secret потребителя.
- Таблицы адресов и SSO, схемы C2 и кейс 06 несут `dsh`; правки — в том же проходе, что и ADR.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Один рантайм (только Hermes) | не показывает второй класс: песочницу с permissions и плагинную расширяемость агентского цикла |
| Мультипользовательский agent-harness (исходная заготовка шага 4) | тянул свой PostgreSQL/app-слой и организацию ради многопользовательской работы; сцена — два личных агента за одним SSO; спека снята из репозитория 2026-11-17 |
| Десктоп-приложение dsh на ноутбуке / облачные агенты | вне контура: нет SSO стенда, нет MCP каталога, нет DLP-пути через `llm-svc.` |

## Откат

`dsh` не задеплоен: откат = не заводить каталог `gitops/apps/dsh/` и маршрут `dsh.`. Снятая спека
прежнего кандидата восстанавливается из истории git (последний коммит до 2026-11-17). Клиент `dsh` в
Keycloak и файл `dsh.local.md` создаются при развёртывании, в git не попадают.
