# Боковичок: 27B на одной 16-ГБ карте без кластера (BeeLlama)

> **Что это.** Автономная рецептура: поднять OpenAI-совместимый `llama-server` из форка
> **BeeLlama.cpp** (Anbeeld, sm_120) с `Qwen3.8-27B-GSQ-RCO-IQ3_S-mtp` — спекулятивное
> декодирование **MTP**, KV-кэш **kvarn4** с precision-tail 2048, контекст **128K** — на **одной
> карте RTX 50-й серии 16 ГБ**. Без k8s, без GPUStack, без шлюза и SSO: один хост, один процесс,
> один эндпоинт `http://<host>:8081/v1`.
>
> **Зачем.** Кейс 01 стенда — та же сборка, но моделью GPUStack
> (`../architecture/specs/gpustack-custom-backend-spec.md`). Здесь — путь для того, у кого карта есть,
> а оркестратора нет: не нужен ни кластер, ни GPUStack, только `runbook-host-run.md`. Каталог же
> остаётся источником эталонных флагов `llama-server` и цифр «было/стало» для кейса 01.

## Когда этот путь, а когда кейс 01

| Ситуация | Куда идти |
|---|---|
| Одна карта, нужен локальный 27B со 128K, кластера нет | **этот каталог**, `runbook-host-run.md` |
| Модели как сервис: несколько моделей, деплой/остановка из UI, ключи, маршруты | кейс 01 + `../architecture/specs/gpustack-custom-backend-spec.md` |
| Нужен замер скорости любого OpenAI-совместимого эндпоинта | `bench_speed.py` (только stdlib) |

## Что нужно

- карта NVIDIA RTX 50-й серии **16 ГБ** (sm_120: 5060 / 5060 Ti / 5070 Ti / 5080 / 5090);
- драйвер с CUDA 13 — в `nvidia-smi` строка `CUDA Version: 13.x` (практически ≥ 580);
- **≈16 ГБ** на диске: дистрибутив 0.64 ГБ + CUDA runtime ≈1.1 ГБ + модель 12.12 ГБ
  (12 120 016 960 байт); runbook §1 страхуется требованием ≥ 40 ГБ свободно;
- ≥ 16 ГБ RAM;
- контейнер-рантайм — по желанию: на Ubuntu-хосте прогон работает и **native**, без podman
  (так он и поднят на ноде стенда, см. `deploy-report-2026-10-16.md`).

## Быстрый старт

Полный порядок с гейтами — `runbook-host-run.md`. Ниже — карта шагов, чтобы понять объём.

| Шаг | Что делаем | Гейт |
|---|---|---|
| 1 | `llama-cli --list-devices` видит карту (≈15 8xx MiB free) | иначе стоп: доступ к GPU не настроен |
| 2 | контейнер или native-запуск на хосте (§2, вариант A/B/C) | `ls /dev/nvidia0` внутри контейнера |
| 3 | дистрибутив BeeLlama v0.4.8 + `sha256sum -c` (§3) | `ecb72ac0…1837` |
| 4 | CUDA runtime 13.3 (prebuilt его **не** включает) → `LD_LIBRARY_PATH` (§4) | `--list-devices` печатает `CUDA0: … RTX 50xx` |
| 5 | модель IQ3_S-mtp, sha256 (§5) | `58fd8267…c12f`, размер 12 120 016 960 |
| 6 | `llama-server` с эталонными флагами (§6) | `curl localhost:8081/health` → `{"status":"ok"}` |
| 7 | приёмка (§7): alias, completion, `draft acceptance`, VRAM | 6 пунктов §0 |
| 8 | стресс-тест «иглой» на 60K (§8) | ответ содержит `изумруд-7742-дельта` |

## Ожидаемые цифры

Один конфиг (27B IQ3_S-mtp, kvarn4, tail 2048, `-c 128000`, `-np 1`), один и тот же `bench_speed.py`,
две разные карты. 5070 Ti — среднее по двум прогонам, 5060 Ti — один прогон; `cached_tokens = 0`
(холодный prefill):

| Карта | Контекст | TTFT | prefill (server) | decode | MTP accept |
|---|---:|---:|---:|---:|---:|
| RTX 5060 Ti 16 ГБ (16.10.2026) | 4K / 32K / 126K | 5.5 / 46.9 / 257 с | 782 / 706 / 496 tok/s | 48.8 / 40.0 / 23.2 tok/s | 61–63 % |
| RTX 5070 Ti 16 ГБ (09.11.2026) | 4K / 32K / 126K | 3.2 / 26.6 / 148 с | 1400 / 1247 / 861 tok/s | 79.3 / 62.1 / 42.1 tok/s | 46–62 % |

Разница 1.6–1.9× — карта, не софт: тот же GGUF, те же флаги, тот же бенчмарк.
VRAM под нагрузкой — коридор **15.0–15.6 ГиБ из 16**, карта строго эксклюзивна.
Действующие цифры и журнал прогонов — `architecture/specs/gpustack-custom-backend-spec.md` §5;
машинные результаты — JSON в этом каталоге (`bench_speed.py` рассчитывает те же метрики).

## Чего здесь нет

- кластера, GPUStack, ключей, маршрутов, стража и шлюза — это кейс 01 и спека custom backend;
- мультиплексирования: `-np 1`, один слот, запросы последовательные (в кейсе 01 это проговаривается вслух);
- автозапуска при ребуте: systemd-unit сознательно не делался — на стенде нода уходит под
  kubelet/GPUStack, сервис удобнее держать деплоем кластера;
- контейнерного варианта на Ubuntu-хосте: не проверялся, на ноде сочли лишним (почему — в отчёте).

## Что проверено, а что нет

- **Проверено:** приёмка runbook §0 на эталоне 16.10.2026 (RTX 5060 Ti, Fedora 44, драйвер 615.71.09);
  тот же конфиг на k8s-04 (Ubuntu 24.04.4, драйвер 595.99.02) **без контейнера** — с одной оговоркой:
  `draft acceptance` по токенам 0.56 при пороге 0.60 (среднее по запросам 0.63); разбор — в отчёте.
  Замеры 09.11 повторены на RTX 5070 Ti тем же бенчмарком.
- **Не проверено:** вариант с контейнером на Ubuntu; релизы BeeLlama после v0.4.8 (хелпер обновления
  с авто-откатом — §11 runbook, на стенде не гонялся).
- **Состояние на 2026-11-19:** хостовый `llama-server` на порту 8081 не отвечает, инстанс GPUStack
  на 40001 тоже (модель выключена между показами) — рецептура лежит, а не работает 24/7.
  Готовность стенда — `scripts/k8s_health.py`.
