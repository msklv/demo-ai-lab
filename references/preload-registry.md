# Склад предзагрузки: реестр по этапам + fetch/push

## Зачем

Канал площадки 4–6 МБ/с, а `registry.k8s.io` и `public.ecr.aws` с неё вообще таймаутят. Всё, что
демо тянет из интернета (образы, чарты, модели), готовится на машине с быстрым каналом и привозится
по LAN. На сцене качать нечего: pull на сцене = десятки минут тишины.

Принцип наполнения: **только то, что штатно поддерживает платформа** (для стенда — каталог раннеров
GPUStack). Неподдерживаемое (кастомные бэкенды, GGUF под llama.cpp) в реестр не попадает даже как
«альтернатива» — владелец такие пункты вычёркивает.

## Где живёт — текущее состояние

**Реестр (постоянная часть):** `preload-registry/` в КОРНЕ репо, **трекается в git**: `docker-compose.yml`
(`registry:2` с пином по digest, порт 5050, том `preload_registry`) + короткий `README.md`.
Запуск/статус/остановка — одной строкой из корня репо (`docker compose -f preload-registry/docker-compose.yml …`),
адрес консоли `192.168.10.188:5050` (статический DHCP-лиз на MikroTik; порт 5050, потому что 5000/7000 на macOS
занял AirPlay). В LAN у бука может быть два адреса — брать тот, что реально отвечает с ноды.

**Склад предзагрузки:** `preload/` в корне репо под правилом `.gitignore` `/preload/` (внутри репо, но не в git —
там реальные размеры, диджесты, имена реестров). Сейчас каталог **пуст**: схема переделывается, прежний набор
(`registry.yaml`, `registry.py`, `fetch.sh`, `push.sh`, `registry-hosts.sh`, `manifest.tsv`, `images/`,`charts/`,`models/`)
снят целиком в локальный архив бэкапов. Не описывать эти скрипты как живущие в репо —
при переделке воспроизводить процедуру из этого файла заново.

## Формат реестра — режется по этапам демо

`stages[]: {id, name, items[]}`, этапы = этапы выступления: **0 инфраструктура → 1 GPUStack →
2 сервисы → 3 агенты**. Плоский список владелец не принимает — нарезка по этапам нужна, чтобы
готовность и трафик считались по шагу демо, а не «вообще».

Запись: `kind` (`image`|`chart`|`model`), `ref` для образа и чарта (**для модели — `repo` HF**, скрипт
нормализует его в то же поле), `version`, `pin` (digest), `size_mb`, `required`, `target` (ноды или
«все ноды»), `status` (`confirmed`|`todo`), `note`. Непроверенное — `status: todo` + в `note`
команда проверки; догадка не выдаётся за ref (`???/repo:???` честнее выдуманного тега).

## Процедура

1. `python3 registry.py summary` — объёмы по этапам и список `todo`.
2. `./fetch.sh --stages 0,1` на машине с быстрым интернетом → `images/*.tar` (docker-archive),
   `charts/*.tgz`, `models/<repo-slug>/` (каталог репозитория целиком); `manifest.tsv` = ref, digest,
   размер, sha256 (только веса, без конфигов).
3. `./push.sh --nodes k8s-04` по LAN: `scp` → `ctr -n k8s.io images import`; модели — подкаталогами
   в `/var/lib/gpustack/models/<repo-slug>/` (`PRELOAD_MODELS_DIR`), чарты — в `/opt/preload/charts`.
4. `./push.sh --verify-only` — приёмка по нодам (что лежит, что нет).
5. Полные диджесты из `manifest.tsv` перенести в `pin:` записей реестра: тег не гарантирует тот же бинарь.

## Грабли (проверены на живом складе)

- **`skopeo copy --all` + `docker-archive` несовместимы** («does not support copying multiple images
  as a group»): архив держит один образ, копировать надо `--override-os linux --override-arch amd64`.
- **`skopeo inspect` на arm64-консоли падает** «no image found in manifest list for architecture
  arm64/darwin» — тот же `--override-arch amd64` обязателен и для inspect, иначе digest пустой и сверка
  вырождается в «grep по пустой строке» = ложно-зелёная.
- **Сверять залитое по имени в CRI, не по digest:** digest манифест-листа в реестре ≠ digest одиночного
  манифеста после импорта; `ctr -n k8s.io images ls -q` даёт только имена (digest — в выводе без `-q`).
- **Пустые поля в TSV ломают bash:** `read` с `IFS=$'\t'` схлопывает подряд идущие табы (таб —
  whitespace) и колонки съезжают. Обмен между скриптами — через US (0x1f) и `IFS=$'\x1f'`;
  `awk -F'\x1f'` в macOS `\x` не понимает — awk для нарезки не использовать.
- **`ssh` внутри `while read` съедает stdin** — обрабатывается только первый элемент; `ssh -n`.
- **Модель — каталог, а не файл:** AWQ-репозиторий это 2 шарда + конфиги; `push.sh` кладёт файлы
  подкаталогом `<repo-slug>/`, иначе vLLM не соберёт модель. Фильтр `--only` должен матчить и `id`,
  и `ref` (у чартов ref = `cilium/cilium:1.20.3`, подстрока «chart» есть только в id).
- `tac` в macOS нет (дедуп манифеста — на python); имя файла чарта не равно имени чарта
  (`node-feature-discovery-chart-0.20.0.tgz`) — искать tgz по подстроке версии; `helm repo add`
  требует уникального имени на URL (генерить из хеша URL).
- Gated-репозиториев в штатном списке быть не должно: если модель требует `HF_TOKEN` и acceptance,
  это повод пересмотреть выбор модели, а не тащить токен в склад.
- Реестры со стенда: `docker.io` / `ghcr.io` открыты, `registry.k8s.io` отдаёт 307 на
  `europe-west3-docker.pkg.dev` и таймаутит — такие образы качать только на «быстрой» машине.

## Транспорт: тары против локального реестра

Решение владельца — обсуждать транспорт отдельно от списка: склад (`registry.yaml`) остаётся, меняется
только доставка. Оба пути проверены на стенде.

| Критерий | тары + `ctr images import` | локальный реестр на буке |
|---|---|---|
| Проверено | да, приёмка `--verify-only` по имени в CRI | да для заливки/`ctr pull`; **kubelet-путь не подтверждён** |
| Зависимости | ssh + sudo, ничего не должно быть запущено | сервис жив на буке, `certs.d`/TLS на нодах |
| Диск на буке | вторая копия (53 ГБ таров) | одна копия (skopeo пишет сразу в реестр) |
| Повторная заливка | весь объём заново | дедуп слоёв |

**Какой реестр поднимать:** `registry:2` (58 МБ, один контейнер, multi-arch → нативно на Apple
Silicon). Harbor для этой задачи не нужен: его стабильные релизы (`v2.14.x`, `v2.15.x`) — **только
amd64** (arm64 живёт лишь в `dev-arm64`-тегах), т.е. на arm64-буке это qemu + 8 контейнеров +
Postgres/Redis/Trivy и 4–8 ГБ RAM ради UI/сканёра, которых в preload-сценарии не используют. Proxy-cache
— единственная фича Harbor, которая тут была бы полезна.

Порядок, если реестр всё-таки поднимаем:

1. Реестр — `docker compose -f preload-registry/docker-compose.yml up -d` (образ запинен digest;
   том именованный, если он создан не compose — при каждом `up` будет warning, это нормально;
   **переименование/перенос файла compose оставляет старые метки проекта** — `docker compose ls` покажет
   мёртвый путь, а `up` из нового места ничего не пересоздаст: лечится `up -d --force-recreate`).
2. Проверить, что ноды вообще видят бук: `ssh <node> 'curl -s -o /dev/null -w "%{http_code}" http://<ip>:<port>/v2/'`.
   У бука в LAN может быть два адреса (Wi-Fi и Ethernet в одной подсети) — ноды обычно видят только
   один; адрес брать тот, что реально отвечает с ноды.
3. Заливка без таров: `./fetch.sh --to-registry <ip>:<port>` (skopeo `docker://` → `docker://`,
   `--dest-tls-verify=false`, путь без домена источника: `gpustack/ssh-server`, `metrics-server/metrics-server`).
4. Ноды: `./registry-hosts.sh --registry <ip>:<port> --nodes all` — пишет
   `/etc/containerd/certs.d/<host>/hosts.toml` (зеркало первым, upstream фолбэком).

**Грабли зеркала (важнее самих команд):**

- **`certs.d` нужен под ДВУМЯ именами:** `docker.io` и `registry-1.docker.io` — CRI нормализует ссылку
  и ищет hosts.toml по второму имени; каталог только с `docker.io` ничего не даёт.
- **`config_path` читается при инициализации плагина:** базовый `config.toml` стенда уже содержит
  `config_path` в `[plugins.'io.containerd.cri.v1.images'.registry]`, но после правки нужен
  `systemctl restart containerd` (контейнеры не страдают — шимы живут отдельно; после рестарта
  прогнать health-gate подов).
- **Приёмка — только подом.** `ctr images pull --hosts-dir /etc/containerd/certs.d <ref>` проходит
  всегда и ничего не говорит о kubelet. Тест: залить в реестр образ под несуществующим в интернете
  именем (`preload-test/only-local:v1`) и запустить под с `image: preload-test/only-local:v1`;
  успех = зеркало работает, `ImagePullBackOff` = нет.
- **Если под не тянет — не углубляться в containerd, а возить тарами** (проверенный путь). Следующий
  шаг для зеркала — не `certs.d`, а TLS-реестр с CA в системные корни нод и ссылками вида
  `registry.<домен>/...` в манифестах: этот путь не зависит от CRI-резолвера вообще.
- Гигиена эксперимента: снятие — `./registry-hosts.sh --remove --nodes all`, `docker rm -f preload-registry`
  (том `preload_registry` остаётся), тестовые образы с нод `ctr -n k8s.io images rm <ref>`; `config.toml`
  и поды нод сверить после (diff + health-gate) — эксперимент не должен оставлять хвостов.
