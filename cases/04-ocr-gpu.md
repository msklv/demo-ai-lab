# Кейс 04 — OCR на своём железе: Docling + GLM-OCR на GPU

## Требования: модели на GPU

| Деплой в GPUStack | Состояние | VRAM | Действие человека в UI |
|---|---|---|---|
| `GLM-OCR` (VLM, vision-OCR) | **включить** — развёрнута, id 18 / route 13 (`glm-ocr-spec`) | 12146 из 16311 MiB | `Start` |
| `Qwen3Guard-Gen-4B` | **выключить** (внешних вызовов в кейсе нет) | — | `Stop` |
| `Qwen3.8-27B-UD`, `gemma-4-12B`, `whisper-turbo` | **выключить** | — | `Stop` |

- 5070 Ti: **только VLM-OCR** — так кейс не зависит от внешнего провайдера и от стража. Страж и чат на
  карту рядом не встают: проверено 24.11 — `Qwen3Guard-Gen-0.6B` ушёл в `error`
  (`Free memory on device cuda:0 (2.28/15.47 GiB) … less than desired 0.3 = 4.64 GiB`), пока `GLM-OCR`
  держит ~13 ГиБ. Это ожидаемое поведение набора, а не сбой.
- 780M: не участвует.
- Под Docling (`doc.demo-ai-lab.ru`) GPU не нужен: он рендерит страницу и собирает markdown, распознаёт модель на карте (`doc-spec` §5.1). «GPU нужен только распознаванию» — буквально.

## Сценарий показа (тезисно)

1. **Тезис:** бумага — самый частый вид «данных, которые никуда нельзя отдавать»; поэтому распознавание должно ехать на своём железе, а не в облаке.
2. Гость грузит русский скан (или фото страницы с телефона) в UI `doc.demo-ai-lab.ru` → на экране markdown. **Настраивать нечего: VLM — дефолт** (с 24.11), скан уходит в `GLM-OCR`.
3. **Сравнение:** тот же файл с полем `pipeline = standard` (и `ocr_preset=ru-en`) — тот же markdown, но с CPU. Разница видна на цифрах: у tesseract ИНН и суммы рассыпаются («WAH / /0123456 /»), у `GLM-OCR` — посимвольно; время сервиса ~2 с у обоих путей, из них 0,55 с — сама модель.
4. **Таблицы:** в VLM-режиме таблицу рисует модель (markdown, как она её видит). Нужна структура (ячейки, bbox) — `pipeline=standard` с `do_table_structure`.
5. Показать, что это не «ещё один сервис»: тот же движок доступен агенту как MCP-инструмент, но **только изнутри кластера** (`docling.doc.svc:8000`; наружу `/mcp` снят, ADR-0012) — связка с кейсом 06. Агент через MCP получает тот же VLM-путь по умолчанию.
6. Назвать ограничения: рукопись, повёрнутые сканы, смешанные языки — где тонко.

## Критерий успеха

Кириллица распознана без потерь на выбранном скане, озвучено время на страницу, в логе пода виден вызов модели (`Batch processed` от `api_openai_compatible_engine`). Таблица — как её отрисовала модель; сохранность структуры отдельно проверяется на `pipeline=standard`.

## Подготовка до сцены (блокеры)

- **`GLM-OCR` развёрнута и проверена 2026-11-06.** Веса на ноде (`/var/lib/gpustack/models/glm-ocr`, 2.5 GB,
  sha256 сверен), модель `GLM-OCR` (id 18) и маршрут (id 13), бэкенд `vllm-custom` на официальном образе
  `vllm/vllm-openai:v0.20.1-x86_64`. Тестовый скан распознан посимвольно через `api.demo-ai-lab.ru` за
  **0.40 с** (прогретый — 0.19 с), VRAM 12146/16311 MiB. Встроенный раннер `gpustack/runner:cuda13.0-vllm0.25.1`
  для этой модели непригоден (деградация текста) — не использовать. Детали, грабли и приёмка —
  `architecture/specs/glm-ocr-spec.md`; smoke-тест — `scripts/glm_ocr_smoke.py`.
  **Перед сценой:** `Stop` 27B/whisper/стража (util 0.9 занимает 12 из 16 GiB), затем `Start GLM-OCR`.
- **VLM — дефолт Docling с 2026-11-24** (`doc-spec` §5.1, приёмка D7): документ из UI/OWU/агента уходит в
  `GLM-OCR` **без параметров**, markdown за ~2 с на страницу; CPU — только явным `pipeline=standard`.
  Модель обязана быть поднята до показа: иначе падает **обычная** конвертация (R-D13), это главный риск сцены.
- Проверить перед выходом: `capabilities.pipelines.default == vlm`, `stages.vlm_pipeline.default == glm-ocr`,
  тестовый скан → `success` (фаза D7). В логе пода должна быть строка `vlm_pipeline_preset default -> glm-ocr`.
- Кириллица в CPU-пути работает **только с явным пресетом** (`ocr_preset=ru-en` или `rapid-ru`); без него сервер идёт `auto` (RapidOCR `ch`) и кириллица распознаётся плохо.
- Подготовить 2–3 документа: хороший скан с таблицей, плохой скан/фото, документ со смешанным рус/англ.

## Фолбэк

Модель не поднялась или карту занял 27B → переключить в UI `pipeline = standard` (+`ocr_preset=ru-en`) и
отработать кейс как «CPU против GPU»: тот же документ, кириллица с потерями в ИНН/суммах, 2–4 с на страницу.
GPU-часть — слайдом с замерами (`glm-ocr-spec` §9.1). Так кейс не выпадает из программы полностью.
