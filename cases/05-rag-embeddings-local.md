# Кейс 05 — RAG: эмбеддинги и реранк на стенде, генерация снаружи

## Требования: модели на GPU

| Деплой в GPUStack | VRAM | Действие человека в UI |
|---|---|---|
| `Qwen3Guard-Gen-4B` (без него внешний маршрут отдаёт `503`) | ≈12.7 GiB на 5070 Ti | `Start` |
| `bge-m3` (эмбеддинги) — **на 780M k8s-01** | 1.37 GiB GTT | `Start` |
| `bge-reranker-v2-m3` (реранк) — **на 780M k8s-01** | ≈1.4 GiB GTT | `Start` |

- 5070 Ti занята только стражем: генерация **внешняя**, локальная LLM не нужна.
- 780M: два pooling-инстанса — модели GPUStack (бэкенд `vllm-rocm-igpu-custom`, образ
  `runner:rocm7.2-vllm0.25.1`, `HSA_OVERRIDE_GFX_VERSION=11.0.0`), селектор **`k8s-01:rocm:0`**. Проверять не
  «780M в свойствах», а **`rocm`-устройство в инстансе** и GTT на ноде: пара держит **2.77 из 11.63 GiB**
  (замер 04.11: 2835 из 11908 MiB). Механика и грабли — `gpustack-spec` §4.6.
- Внешняя генерация — `llm-svc.` (статический ключ), то есть через DLP и страж, а не напрямую в провайдера.

## Сценарий показа

1. **Тезис:** «в RAG дорогая часть — не генерация, а поиск; поиск остался на стенде, наружу ушёл только
   отобранный контекст».
2. Гость открывает `rag.demo-ai-lab.ru`, выбирает заранее проиндексированную базу.
3. Вопрос из зала → на экране топ-k чанков **после реранка** (`bge-reranker-v2-m3`), а не сырые результаты.
4. Ответ генерации с цитатой на фрагмент документа.
5. **Контраст:** тот же вопрос напрямую внешней модели (без RAG) — ответ общий, без опоры на документ стенда.
6. Показать, где считается эмбеддинг/реранк: инстансы на 780M, метрики/логи GPUStack; ни один чанк корпуса
   наружу не уходит — только выбранные.
7. (По желанию) тот же поиск через API — чтобы зал увидел, что это не «только UI».

## Критерий успеха

Ответ со ссылкой на конкретный фрагмент базы; в логах виден вызов `bge-m3` и `bge-reranker` на 780M до
обращения к `llm-svc`; страж включён (внешний вызов прошёл, а не `503`).

## Подготовка до сцены

- **RAGFlow не развёрнут** (запись каталога `ru.demo-ai-lab/ragflow@1.0.0` опубликована 17.11, но
  `rag./api/v1/mcp` ответит только после деплоя). План, модели, лимиты и приёмка — `rag-spec` (R1–R9); SSO у
  RAGFlow нет — вход по паролю. RAM-блокер (стек ≈10–12 GiB) снимается размещением на k8s-01/05.
- **`bge-m3` и `bge-reranker-v2-m3` задеплоены 03.11** (`vllm-rocm-igpu-custom`), приёмка с публичного
  маршрута: `/v1/embeddings` → 200 (dim 1024, 0.18 с тёплый), `/v1/rerank` → 200 (0.08 с тёплый). Перед
  сценой — только `Start`. **Не запускать с дефолтными параметрами:** первый старт без `util 0.12` /
  `ctx 4096` валит ноду в GPU Hang (`gpustack-spec` §4.6, п. 4) — параметры должны быть в модели до `Start`.
- Индекс базы строится **до** сцены: первый парсинг документа 5+ минут.

## Фолбэк

**Основной фолбэк — RAG самого Open WebUI (`owu.demo-ai-lab.ru`)**: с 03.11 он считает эмбеддинги `bge-m3` и
реранк `bge-reranker-v2-m3` на 780M (`owu-spec` §7.4). Сценарий тот же: загрузить документ в Knowledge →
задать вопрос → показать топ-чанки после реранка и ответ с опорой на фрагмент. Плюс: не нужен отдельный
стек RAGFlow и тот же вход по SSO.

Если и это недоступно — показать связку «эмбеддинг+реранк на 780M» прямым API (два `curl`: `/v1/embeddings`,
`/v1/rerank`) и рассказать, что именно эти два вызова дают RAG; затем перейти к кейсу 06.
