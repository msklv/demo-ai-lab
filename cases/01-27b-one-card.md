# Кейс 01 — «27B на одной карте» (флагман)

## Требования: модели на GPU

| Деплой в GPUStack | Состояние | VRAM | Действие человека в UI |
|---|---|---|---|
| `Qwen3.8-27B-UD` (BeeLlama custom backend, `Qwen3.8-27B-GSQ-RCO-IQ3_S-mtp`, ctx 128000) | **включить** | 15.1–15.6 GiB из 15.93 | `Model Service → Deployments → Start` |
| `gemma-4-12B` | **выключить** | — | `Stop` |
| `whisper-turbo` | **выключить** | — | `Stop` |
| `Qwen3Guard-Gen-4B` | **выключить** | — | `Stop` |

- Карта только эксклюзивно: любой сосед = CUDA OOM (custom backend не заявляет VRAM планировщику, риск R-B1).
- 780M: свободна, в кейсе не участвует.
- **Внешний маршрут (`llm.`/`llm-svc.`) в это время не работает** — страж выключен, fail-closed. Внешних вызовов в кейсе нет.
- Проверка перед выходом на сцену: `nvidia-smi` на k8s-04 → занято 15.1–15.6 GiB, свободно < 0.5 GiB; в логах инстанса `kv cache type = kvarn4`, `n_ctx = 128000`.

## Сценарий показа (тезисно)

1. **Тезис на слайде:** 27B в 3-битном кванте + 4-битный KV + спекулятивное декодирование (MTP) — отсюда 128K контекста на 16 ГБ.
2. Карточка модели в UI GPUStack: имя, бэкенд `beellama-custom`, параметры запуска (все флаги видны).
3. Живой запрос через API (`llm-svc` не нужен — прямой `/v1/chat/completions` к `api.`): короткий ответ, чтобы зал увидел скорость.
4. **Needle 60K**: заранее подготовленный длинный документ с иглой в середине → модель находит (`изумруд-7742-дельта`). Это главный визуальный момент кейса.
5. Цифры на слайд: decode ~43 tok/s, MTP accept 0.56–0.66, prefill 742 tok/s — сняты на bare-metal, на сцене воспроизводятся.
6. **Concurrency 1** — сказать вслух: `-np 1`, один слот, поэтому «попробовать самому» в этом кейсе нельзя; интерактив для зала начинается со следующего.
7. Ключ API: в UI GPUStack создать ключ (`API Keys → Create`, доступ только к `Qwen3.8-27B-UD`) — показать, что модель выдаётся как обычный OpenAI-совместимый эндпоинт.
8. (Опционально) OWU: отдельное подключение на `api.` с этим ключом — если хотим показать модель в чат-интерфейсе. Тогда нужен ещё один шаг подготовки (см. «Блокеры»).

## Критерий успеха

Непустой ответ + найденная игла на 60K + VRAM в коридоре 15.1–15.6 GiB + 0 рестартов пода за кейс.

## Подготовка до сцены (блокеры)

- Прогон `beellama-rtx5060/SPEC-gpustack-custom-backend.md` **B0–B7**: регистрация бэкенда `beellama-custom`, каталог модели `/var/lib/gpustack/models/beellama-qwen38`, деплой `Qwen3.8-27B-UD`, ключ `beellama-test`. Сейчас спека в статусе «не выполнено».
- Образ `nvidia/cuda:13.3.0-runtime-ubuntu24.04` прогрет на k8s-04 (иначе первый старт = `ImagePullBackOff`).
- Ключ демо/`beellama-test` создан, права только на эту модель; ключи `owu`/`spk` не трогать (после возврата `gemma` они должны работать).
- Если показываем через OWU — добавить подключение на `api.` с ключом только к `Qwen3.8-27B-UD` (в БД OWU, см. `architecture/specs/owu-spec.md` §7.1).

## Фолбэк

Модель не поднялась → включить `gemma-4-12B` (12.6 GiB) и рассказать бюджет квантов на слайде; needle на 12B не показывать (ctx 8192). Внешний маршрут в этом случае тоже недоступен (страж выключен) — переходить к кейсу 02 только после `Stop` 27B и `Start` стража.
