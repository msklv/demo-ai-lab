# Кейс 01 — «27B на одной карте» (флагман)

## Требования: модели на GPU

| Деплой в GPUStack | VRAM | Действие человека в UI |
|---|---|---|
| `Qwen3.8-27B-UD` (BeeLlama custom backend, `Qwen3.8-27B-GSQ-RCO-IQ3_S-mtp`, ctx 128000) | 15.1–15.6 GiB из 15.93 | `Model Service → Deployments → Start` |

- Карта только эксклюзивно: любой сосед = CUDA OOM (custom backend не заявляет VRAM планировщику, R-B1).
- 780M свободна. **Внешний маршрут (`llm.`/`llm-svc.`) в это время не работает** — страж выключен,
  fail-closed; внешних вызовов в кейсе нет.
- Проверка перед выходом на сцену: `nvidia-smi` на k8s-04 → занято 15.1–15.6 GiB; в логах инстанса
  `n_ctx_slot = 128000`, `kv_unified = 'true'`, `creating MTP draft context` (буквальной строки
  `kv cache type = kvarn4` в логах v0.4.8 нет; 4-битный KV подтверждается коридором VRAM и needle 97K).

## Сценарий показа

1. **Тезис на слайде:** 27B в 3-битном кванте + 4-битный KV + спекулятивное декодирование (MTP) — отсюда
   128K контекста на 16 ГБ.
2. Карточка модели в UI GPUStack: имя, бэкенд `beellama-custom`, параметры запуска (все флаги видны).
3. Живой запрос через API (прямой `/v1/chat/completions` к `api.`, `llm-svc` не нужен): короткий ответ,
   чтобы зал увидел скорость.
4. **Needle 60K** — главный визуальный момент: заранее подготовленный длинный документ с иглой в
   середине, модель находит `изумруд-7742-дельта`.
5. Цифры на слайд (**замер 2026-11-09, RTX 5070 Ti**): decode **~81 tok/s** на коротком контексте и
   **~42 tok/s** на 128K, prefill **~1400 tok/s**, MTP accept 0.46–0.62. Два прогона `bench_speed.py`
   (cold cache): decode 80.8/77.7 · 65.4/58.8 · 42.5/41.7 tok/s (4K/32K/max), TTFT 3.2/26.6/148 с —
   журнал `architecture/specs/gpustack-custom-backend-spec.md` §5. Прогон 02.11 на 5060 Ti дал
   44.7/38.6/21.7 tok/s: разница в 1.7–1.9× — это карта, а не софт.
6. **Concurrency 1** — сказать вслух: `-np 1`, один слот, «попробовать самому» в этом кейсе нельзя,
   интерактив для зала начинается со следующего.
7. Ключ API: создать в UI (`API Keys → Create`, доступ только к `Qwen3.8-27B-UD`) — модель выдаётся как
   обычный OpenAI-совместимый эндпоинт.
8. **OWU:** модель видна в чате через основное подключение `api.` — один ключ `owu-all` на все модели,
   список показа режет фильтр `model_ids` (`owu-spec` §7.2).

## Критерий успеха

Непустой ответ + найденная игла на 60K + VRAM в коридоре 15.1–15.6 GiB + 0 рестартов пода за кейс.

## Подготовка до сцены — исполнено 2026-11-02/03

- B0–B5 спеки `architecture/specs/gpustack-custom-backend-spec.md` прогнаны в тестовом окне (журнал §5, приёмка §1 PASS):
  бэкенд `beellama-custom` зарегистрирован, каталог `/var/lib/gpustack/models/beellama-qwen38` на месте,
  модель держит коридор VRAM. Остаток B6–B7 — возврат резидентов после показа, по команде.
- Образ `nvidia/cuda:13.3.0-runtime-ubuntu24.04` прогрет на k8s-04; ключ `beellama-test` создан (значение
  — в приватном хранилище, доступ только к `Qwen3.8-27B-UD`); ключи `owu`/`spk` не тронуты.

## Фолбэк

Модель не поднялась → включить `gemma-4-12B` (12.6 GiB) и рассказать бюджет квантов на слайде; needle на
12B не показывать (ctx 8192). Внешний маршрут в этом случае тоже недоступен (страж выключен) — к кейсу 02
переходить только после `Stop` 27B и `Start` стража.
