# AGENTS.md — правила работы с репозиторием

## Состояние стенда — начинать со скриптов

Любой вопрос про состояние стенда (после ребута, пересборки, потери питания, обновления) —
сначала `python3 scripts/k8s_health.py` (`--brief` — только WARN/FAIL, `--json` — машинно);
коды выхода `0`/`2`/`1`, прогресс в stderr. Закрывает API/VIP, ноды+pressure, поды, etcd,
control-plane/kube-vip, Argo/Longhorn/Higress, SSH-замер и origin в LAN, а при мёртвом API сама
находит дедлок kube-vip.

Обвязку (внешняя VM-egress с hop-ами, Cloudflare-туннель и внешний путь через edge) проверяет
отдельный `python3 scripts/env_health.py` — те же флаги/коды.
Кластер и обвязку не смешивать: туннель и edge в `k8s_health.py` больше не проверяются.

Дальше — по назначению: **готовность по слоям** (образы, модели, прерогативы фичи, маршруты и доки) —
`architecture/specs/health-check-spec.md` (точка входа и методология); **разбор не-зелёного и
восстановление** — `references/health-runbook.md` (кластер) и
`architecture/specs/external-access-spec.md` §E7 (обвязка).

## Обязательная проверка чувствительности перед коммитом и пушем

**Ничего лишнего в git.** Репозиторий публичный — каждый коммит уходит в открытую историю.
Перед `git commit` и перед `git push` агент обязан прогнать проверку и не коммитить найденное;
при сомнении — остановиться и спросить человека.

### Отчёты по ИБ, уязвимости и разборы инцидентов — только `*.local.md`

**Репозиторий публичный: найденная уязвимость — это карта для атакующего.** Отчёты по ИБ,
пентесты, разборы инцидентов, найденные дыры и способы их эксплуатации в git **не попадают**
никогда — они живут в `security/*.local.md` (подпадает под `*.local.md` в `.gitignore`,
не трекается, не публикуется, не цитируется в чатах и коммитах).

Что уходит в локальный отчёт (`security/<дата>-<тема>.local.md`):

- описание уязвимости, условия эксплуатации, PoC-запросы и payload'ы, шаги воспроизведения;
- точные адреса/порты/пути атакуемой поверхности, если они и есть предмет уязвимости;
- перечни «что открыто без аутентификации», слабые места конфигурации (пароли/хеши, режимы
  без пароля, широкие allowlist'ы), результаты сканов и оценки критичности;
- план устранения с конкретными командами/конфигами, пока он не внедрён.

Что можно и нужно писать в публичных доках (спека, ADR, борд состояния):

- **факт решения и статус**: «периметр служебных путей требует доработки — работы ведутся,
  внешний вход закрыт на уровне security group до их завершения»;
- нейтральную ссылку: «детали — локальный отчёт ИБ от <дата>, вне репозитория»;
- архитектурное решение (PROXY protocol, выделенный порт, allowlist) — без описания того,
  что именно сейчас открыто и как это обойти.

Правило распространяется на всё, что генерирует агент: спеки, ADR, диаграммы (SVG/Excalidraw),
README, комментарии в скриптах и **текст вывода** health-скриптов (публичный скрипт не должен
объяснять найденную дыру — только сигнализировать «не-зелёное» и ссылаться на локальный отчёт).

Проверка перед коммитом — отдельным шагом, вместе с grep-сканом секретов. Смотреть только
**добавленные** строки (`^+`), иначе удаление старого текста само даёт хиты:

```bash
git diff --cached --unified=0 | grep '^+' | grep -inE -e 'CVE-[0-9]{4}' -e 'уязвим' -e 'эксплуатир|exploit' \
  -e 'пентест|pentest' -e 'noPassword' -e '\bPoC\b' -e 'обход (allowlist|фильтр|правил)'; echo "rc=$?"
# rc=0 — разбирать: такое живёт в security/*.local.md, в публичном тексте — только статус и ссылка
```

Ложные срабатывания, которые не считать нарушением: слово «эксплуатация» в смысле сопровождения
(`Кластер и эксплуатация`, «выведен из эксплуатации»), версии и хеши, `*.local.md` (в git их быть
не должно — проверяется отдельным правилом выше).

### Что категорически нельзя публиковать

- **Секреты и токены**: пароли, API-ключи, токены GitHub (`ghp_*`, `github_pat_*`),
  Hugging Face (`hf_*`), облачных провайдеров, приватные SSH-ключи (`BEGIN ... PRIVATE KEY`),
  содержимое `.env`-файлов.
- **Идентификаторы оборудования и доступа**: MAC-адреса (в т.ч. OUI-привязки как «этот MAC = этот
  хост»), логины вида «юзер@хост» с реальными именами, пути к
  ssh-ключам `/home/<login>/.ssh/...`, парольные/ключевые материалы из inventory.
- **Внешние адреса площадки**: public IP (помечен `[confidential]`), адреса/координаты/названия
  физической площадки, где размещён стенд, любые данные, по которым MacBook-консоль или узел
  стенда можно идентифицировать снаружи (серийники, hostname с ФИО).
- **Исключение**: `demo-ai-lab.ru` — публичный бренд стенда, публикуется (см. ниже).
- **Аккаунты внешних служб**: любые учётные данные GitHub / Hugging Face / провайдеров, сессии,
  куки, персональные токены.
- **Файлы приватной инвентаризации**: `inventory.local.md`, `*.local.md` (в т.ч.
  `keycloak-admin.local.md`, `keycloak-users.local.md`, `keycloak-clients.local.md`,
  `mcp-registry.local.md`, `yandex-search.local.md`), `*.local.pem` (приватный ключ Ed25519
  для публикации в каталоге MCP — `mcp-publisher.local.pem`), `.env*` — они в `.gitignore`,
  публикация запрещена всегда.

### Что публикуется осознанно (операционная документация стенда)

Схема сети с LAN-диапазонами (`192.168.10.0/24`, `10.20.20.0/26`), IP узлов k8s-01…k8s-04,
настройки MikroTik (но без логина, пароля и ключей Wi-Fi), роли и состояние стенда — это
содержимое доков по назначению (`network-map-detail.md`, `architecture/ARCHITECTURE.md`, диаграммы).

- **Публичное имя лаборатории `demo-ai-lab.ru`** — публикуется и коммитится свободно:
  это публичный бренд стенда, должен присутствовать в доках. Public IP остаётся `[confidential]`.

### Код и команды в репозитории

- Креды — только из окружения или `inventory.local.md`. В скриптах и плейбуках фигурируют
  **имена** ресурсов (`secret cert-manager/cloudflare-api-token`, `lookup('env', ...)`),
  никогда значения, логины и пути к ключам.
- Команды забора паролей и токенов в файлы не печатать: вместо конкретных env-переменных с
  паролями и путей к хранилищу — формулировка «экспортируется из локального приватного хранилища».

### Процедура перед `git commit`

1. `git status --porcelain` — в выводе нет приватных путей. Отдельно проверить, что ни один приватный
   файл не попал в индекс — **по правилам, а не по списку имён** (список устаревает: в репо уже 13
   таких файлов):
   ```bash
   git ls-files | grep -E '\.local\.(md|pem)$|(^|/)\.env'; echo "rc=$?"   # rc=1 — приватных в git нет
   ```
   Правила `.gitignore` — `inventory.local.md`, `*.local.md`, `*.local.pem`, `.env*`; они покрывают
   `keycloak-*`, `gpustack-admin`, `spk-admin`, `owu-admin`, `higress-console-admin`, `argocd-admin`,
   `llm.local`, `mcp-registry`, `yandex-search`, `mcp-publisher.local.pem`. Новый `*.local.md`
   подхватывается без правки процедуры.
2. Прогнать по staged-диффу grep-скан:
   ```bash
   # Шаблон НЕ должен начинаться с дефиса: BSD grep (macOS) примет его за опцию —
   # «grep: unrecognized option», rc=2, а пустой вывод читается как «чисто».
   # Поэтому -e на каждую альтернативу и явная проверка кода возврата.
   git diff --cached | grep -inE -e '-----BEGIN (RSA|OPENSSH|EC|DSA|PGP|PRIVATE)' -e 'ghp_[A-Za-z0-9]{20,}' \
     -e 'github_pat_' -e 'hf_[A-Za-z0-9]{20,}' -e 'AKIA[0-9A-Z]{16}' -e 'password' -e 'passwd' \
     -e 'token' -e 'secret' -e 'api[_-]?key'; echo "rc=$?"
   git diff --cached | grep -inE -e '([0-9a-f]{2}:){5}[0-9a-f]{2}'; echo "rc=$?"
   git diff --cached | grep -inE -e 'msklv[0-9]+@' -e 'sokolov' -e 'соколов'; echo "rc=$?"
   # внешние IP: всё, что не документированные LAN-диапазоны
   git diff --cached | grep -inE -e '([0-9]{1,3}\.){3}[0-9]{1,3}' \
     | grep -vE -e '192\.168\.10\.' -e '10\.(20\.20|0\.[0-9]+)\.' -e '127\.0\.0\.1' -e '0\.0\.0\.0'; echo "rc=$?"
   ```
   Коды возврата: `0` — есть хиты (разбирать), `1` — совпадений нет (чисто), `2` — шаблон или путь
   сломан: **не считать «чисто»**, перезапустить проверку. Любой хит разобрать: если это реальное
   значение, а не документированный адрес/заглушка — исключить файл из коммита и спросить человека.
2б. Прогнать скан «отчёт ИБ / уязвимость» по добавленным строкам (правило — раздел
   «Отчёты по ИБ, уязвимости и разборы инцидентов — только `*.local.md`»):
   ```bash
   git diff --cached --unified=0 | grep '^+' | grep -inE -e 'CVE-[0-9]{4}' -e 'уязвим' \
     -e 'эксплуатир|exploit' -e 'пентест|pentest' -e 'noPassword' -e '\bPoC\b' \
     -e 'обход (allowlist|фильтр|правил)'; echo "rc=$?"
   ```
   `rc=0` — разбирать каждый хит: описание дыры, PoC, «что открыто без аутентификации» и план
   устранения уходят в `security/<дата>-<тема>.local.md`; в публичном тексте остаётся статус
   («периметр требует доработки, вход закрыт») и ссылка на локальный отчёт.
3. Проверить ссылки в доках: `python3 scripts/check_doc_links.py` — код 0, битых ссылок нет.
4. Проверить, что в индексе нет файлов, которые «выглядят как документ, но содержат лишнее»
   (untracked-файлы тоже: они станут tracked после `git add`).

### Процедура перед `git push`

1. Не пушить `force`-ом без явной команды человека.
2. Проверить remote: `git remote -v` — публикация идёт только в `github.com/msklv/demo-ai-lab`.
3. Перед широким `git add -A` смотреть `git diff -- .gitignore`: снятие правила с приватного
   файла = этот файл уйдёт в коммит — если правило снято, назвать факт человеку до пуша.
4. После пуша проверять по факту на удалённом (`git status -sb`, `git log origin/main`),
   вывод `git push` сам по себе не доказательство.

## Доки о состоянии стенда

Текущее состояние — только в борде `architecture/ARCHITECTURE.md` §7 и в датированных снимках
`architecture/hardware-inventory.md`; остальные разделы ARCHITECTURE (§1–6, §8) — проективные
решения, под сиюминутное состояние их не переписываем. Датированные снимки журнала — история:
устаревшие цифры в них не правим, новое состояние добавляем новой записью с датой.

## Справочные каталоги — не читать без явного запроса

- `old/` — архив выведенных из эксплуатации материалов (storytelling, старые HTML).
- `beellama-rtx5060/` — справочник хостового прогона BeeLlama на RTX 5060 Ti: исследования
  и отчёты. В k8s-инсталляции инференс идёт только через GPUStack (спека §10), каталог
  нужен лишь при явной задаче про хостовый BeeLlama (запуск/стоп/GPU-бенчи по запросу).

Агент НЕ открывает и не цитирует файлы этих каталогов при общих задачах по репозиторию,
аудитах и обновлении доков — только если человек явно попросил про тему каталога.
Файлы не удалять и не переносить без команды.

## Если что-то было запушено

Не молчать: сообщить человеку, что уехало, предложить ротацию скомпрометированных токенов и
переписать историю ТОЛЬКО с явного согласия (amend / filter-repo + force-with-lease).
