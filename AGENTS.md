# AGENTS.md — правила работы с репозиторием

## Состояние стенда — начинать со скриптов

Любой вопрос про состояние стенда (после ребута, пересборки, потери питания, обновления) —
сначала `python3 scripts/k8s_health.py` (`--brief` — только WARN/FAIL, `--json` — машинно; коды
`0`/`2`/`1`, прогресс в stderr): один прогон закрывает кластер целиком (перечень — `scripts/README.md`).

Обвязку (VM-egress, путь через внешнюю VM и hop-ы) проверяет `python3 scripts/env_health.py` —
те же флаги/коды; с кластером не смешивать.

Готовность по слоям и разбор не-зелёного — `architecture/specs/health-check-spec.md` +
`references/health-runbook.md` (обвязка — `architecture/specs/external-access-spec.md` §E7).

## Обязательная проверка чувствительности перед коммитом и пушем

**Ничего лишнего в git.** Репозиторий публичный — каждый коммит уходит в открытую историю.
Перед `git commit` и перед `git push` агент обязан прогнать проверку и не коммитить найденное;
при сомнении — остановиться и спросить человека.

**Классы запрещённого — только `HYGIENE.md`.** Здесь — процедура и гейт; список классов своими
словами не пересказывать.

### Приватные файлы — в git не попадают никогда

`inventory.local.md`, `*.local.md`, `*.local.pem`, `.env*` — правила `.gitignore`, а не список
имён: новый `*.local.md` подхватывается без правки процедуры. Значения из них читаются скриптами
(`scripts/*_secrets.sh`) в переменную и в вывод не печатаются — `cat` приватного файла в чат/лог
такая же утечка, как коммит.

### Код и команды в репозитории

- Креды — только из окружения или `inventory.local.md`; в скриптах и плейбуках фигурируют **имена**
  ресурсов (имена Secret'ов, `lookup('env', ...)`), никогда значения,
  логины и пути к ключам. Забор паролей в команды и файлы не печатать: «экспортируется из
  локального приватного хранилища».

### Процедура перед `git commit`

1. `git status --porcelain` — приватных путей нет; в индексе ни одного приватного файла
   (**по правилам `.gitignore`**, а не по списку имён — список устаревает), и ни одного файла,
   который «выглядит как документ, но содержит лишнее» (untracked тоже: они станут tracked):
   ```bash
   git ls-files | grep -E '\.local\.(md|pem)$|(^|/)\.env'; echo "rc=$?"   # rc=1 — приватных в git нет
   ```
2. Прогнать гейт гигиены по staged-диффу (классы — `HYGIENE.md`, реализация —
   `scripts/hygiene_scan.py`):
   ```bash
   ./scripts/hygiene_scan.py; echo "rc=$?"    # 0 — STOP нет, 1 — STOP есть, 2 — сканер не отработал
   ```
   STOP-хиты не коммитить: значение переносится в `*.local.md` (ИБ — в `security/*.local.md`),
   в публичном тексте остаётся роль без значения. REVIEW-хиты разобрать глазами: «фикстура или
   данные». `rc=2` — вердикт недействителен (сломан git/шаблон), перезапускать, а не считать «чисто».
   Полная проверка дерева и истории: `./scripts/hygiene_scan.py --tree` / `--history`.
   Что сканер не видит и остаётся человеку (ФИО по контексту, EXIF в медиа, текст диаграмм/презентаций,
   сообщение коммита) — `HYGIENE.md` §3.
3. Проверить ссылки в доках: `python3 scripts/check_doc_links.py` — код 0, битых ссылок нет.

### Процедура перед `git push`

1. Не пушить `force`-ом без явной команды человека.
2. Проверить remote: `git remote -v` — публикация идёт только в `github.com/msklv/demo-ai-lab`.
3. Перед широким `git add -A` смотреть `git diff -- .gitignore`: снятие правила с приватного
   файла = этот файл уйдёт в коммит — если правило снято, назвать факт человеку до пуша.
4. После пуша проверять по факту на удалённом (`git status -sb`, `git log origin/main`),
   вывод `git push` сам по себе не доказательство.

## Доки о состоянии стенда

Разделы ARCHITECTURE §1–6 и §8 — проективные решения, под сиюминутное состояние их не переписываем.
Датированные снимки журнала — история: устаревшие цифры в них не правим, новое состояние добавляем
новой записью с датой.

## Правки: жадный режим

**Область — только `*.md`.** Код, манифесты, плейбуки и values этим инвариантом не меряются:
там цель — работающий артефакт и гейты, а не минус строк.

Крупная правка в доках (больше ~10–15 строк в одном `.md` или в наборе доков) — не только дописывание.
Инвариант после правки: **удалённых строк больше, чем добавленных**
(`git diff --cached --numstat -- <paths>`, несведённые — `git diff --numstat`).

Дефицит добирается только по теме правки:

- **вода по теме** — повторы тезиса, вводные абзацы, пересказ самого документа, «что это даёт»;
- **устаревшее** — старый путь, карта, цифра или снятый сервис, которые правка заменяет: удалять,
  а не помечать «история» (датированные снимки журнала и ревизии ADR/спек — исключение);
- **дубли** — то же утверждение в другом доке, таблице, кейсе или спеке: один источник, остальные — ссылкой.

Не считается выполнением: удаление чужих рабочих разделов, «сжатие» за счёт фактов, команд и гейтов.
Если после чистки добавленных всё равно больше — назвать причину в ответе (новый факт) или не делать правку.

## Боковичок: хостовый прогон без кластера

`host-beellama/` — «27B на одной 16-ГБ карте без k8s и GPUStack»: `host-beellama/runbook-host-run.md`
(живая инструкция) + датированный отчёт, research, выбор карты, `bench_speed.py` и замеры;
состав — в `host-beellama/README.md`. Ценность — повтор там, где оркестратора нет; эталон флагов
и цифр «было/стало» для кейса 01. Хостовый запуск — не режим стенда: инференс только через GPUStack
(`architecture/specs/gpustack-custom-backend-spec.md`), а замеры каталога — не текущее состояние.
