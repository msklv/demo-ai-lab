## Микро-бенчмарк скорости

`bench_speed.py` — компактный клиент (только stdlib Python) к OpenAI-совместимому эндпоинту.
Мерит на **3 размерах контекста** (последний — максимальный для запуска) при **parallelism = 1**
(последовательные запросы, без конкуренции):

- **TTFT** — время до первого токена (streaming SSE, включает prefill) — клиентское;
- **prefill tok/s** — скорость обработки промпта (client: `prompt_tokens/TTFT`; server: `timings.prompt_per_second`);
- **decode tok/s** — скорость генерации (client: `(completion−1)/время генерации`; server: `timings.predicted_per_second`);
- **MTP accept** — доля принятых черновиков спекулятивного декодирования;
- **E2E** — полное время запроса.

Филлер — детерминированная кириллица с уникальным seed на прогон (холодный prefill, без
попадания в prompt-cache); соотношение «символы/токен» калибруется одним запросом до замеров.
Максимальный размер задаётся как `max` = `n_ctx − max_tokens − 256`.

### Результаты (RTX 5070 Ti 16 GB, драйвер 595.99.02, k8s-04, PCIe Gen4 x4)

Среднее по двум прогонам 2026-11-09 (`run_salt` 88101 / 88102, тот же seed-филлер, холодный prefill):

| Контекст (prompt_tokens) | TTFT | prefill tok/s (client / server) | decode tok/s (client / server) | MTP accept | E2E |
|---:|---:|---:|---:|---:|---:|
| 4 091 / 4 019 | 3.19 с | 1273 / 1400 | 79.3 / 79.3 | 57 % | 9.6 с |
| 32 664 / 32 602 | 26.56 с | 1229 / 1247 | 62.1 / 62.1 | 50 % | 34.8 с |
| **126 508 / 126 389** (max) | **148.11 с** | 854 / 861 | 42.1 / 42.1 | 61 % | 160.3 с |

Прогоны: `max_tokens=512`, `parallelism=1`, `cached_tokens=0` во всех шести замерах (холодный prefill).
Максимум = 126 508 / 126 389 токенов (цель 127 232 = `n_ctx 128000 − 512 бюджета генерации − 256 запас`).
Машинные результаты — `bench-2026-11-09-run1.json` / `run2.json`.

**Что видно:**
- **TTFT/prefill растёт почти линейно по контексту**: 3.19 с → 26.56 с → 148.11 с; пропускная
  способность prefill падает `1400 → 1247 → 861 tok/s` (серверный замер).
- **Decode падает с ростом контекста вдвое**: `79.3 → 62.1 → 42.1 tok/s` — цена attention
  по удлиняющемуся KV-кэшу (kvarn4, full-attention каждые 4 слоя).
- **MTP acceptance 50–61 %** (у прежней 5060 Ti было 61–63 %): на быстрой карте MTP даёт меньший
  относительный выигрыш — 79.3 против наивного потолка 74.0 (`896/12.11`) = ×1.07, у 5060 Ti было ×1.32.
- Модель запущена с `--reasoning on` (`reasoning_effort=xhigh`): при `max_tokens=512` весь бюджет
  ушёл в reasoning-токены (`visible_tokens=0`) — на скорость генерации это не влияет (токен есть токен).

> Разброс между прогонами есть: decode tok/s зависит от MTP acceptance (наблюдалось 46–62 %);
> по двум прогонам — 79.3 · 77.7 / 62.1 · 58.8 / 42.1 · 41.7 tok/s (4K / 32K / max).

### Воспроизвести

```bash
python3 bench_speed.py --host 192.168.10.252 --port 8081 --json bench-2026-11-09-run1.json
# порт 8081 — хостовый llama-server; инстанс GPUStack (custom backend) слушает 40001
# опции: --sizes 4096,32768,max   --max-tokens 512   --seed N
```

Требуется живой сервер (`curl http://192.168.10.252:8081/health` → `{"status":"ok"}`; для инстанса
GPUStack — `http://192.168.10.252:40001/health`). JSON прогонов 09.11 писать новыми именами:
`bench-results.json` — прогон 16.10 на 5060 Ti, его не перезаписывать.
