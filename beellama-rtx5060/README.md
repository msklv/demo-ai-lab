(Anbeeld, sm_120) со спекулятивным декодированием **MTP** и **KVarN**-квантизацией KV-кэша.
Развёрнуто на GPU-ноде стенда **demo-ai-lab** (k8s-04, `192.168.10.252`), OpenAI-совместимый API
на порту **8081**, alias `Qwen3.8-27B-UD`, контекст **128K** (`n_ctx=128000`).

## Микро-бенчмарк скорости

`bench_speed.py` — компактный клиент (только stdlib Python) к OpenAI-совместимому эндпоинту.
Мерит на **3 размерах контекста** (последний — максимальный для запуска) при **parallelism = 1**
(последовательные запросы, без конкуренции):

- **TTFT** — время до первого токена (streaming SSE, включает prefill) — клиентское;
- **prefill tok/s** — скорость обработки промпта (client: `prompt_tokens/TTFT`; server: `timings.prompt_per_second`);
- **decode tok/s** — скорость генерации (client: `(completion−1)/время генерации`; server: `timings.predicted_per_second`);
- **MTP accept** — доля принятых черновиков спекулятивного декодирования;
- **E2E** — полное время запроса.

Филлер — детерминированная кириллица с уникальным seed на прогон (холодный prefill, без
попадания в prompt-cache); соотношение «символы/токен» калибруется одним запросом до замеров.
Максимальный размер задаётся как `max` = `n_ctx − max_tokens − 256`.

### Результаты (RTX 5060 Ti 16 GB, драйвер 595.99.02, k8s-04, PCIe Gen4 x4)

| Контекст (prompt_tokens) | TTFT | prefill tok/s (client / server) | decode tok/s (client / server) | MTP accept | E2E |
|---:|---:|---:|---:|---:|---:|
| 4 107 | 5.53 с | 742 / 782 | 48.8 / 48.8 | 63 % | 16.0 с |
| 32 538 | 46.86 с | 694 / 706 | 40.0 / 39.9 | 61 % | 59.6 с |
| **126 515** (max) | **256.78 с** | 493 / 496 | 23.2 / 23.2 | 62 % | 278.8 с |

Прогон: `run_salt=202153634`, `max_tokens=512`, `parallelism=1`, `cached_tokens=0` (холодный prefill).
Максимум = 126 515 токенов (цель 127 232 = `n_ctx 128000 − 512 бюджета генерации − 256 запас`).

**Что видно:**
- **TTFT/prefill растёт почти линейно по контексту**: 5.5 с → 46.9 с → 256.8 с; пропускная
  способность prefill падает `782 → 706 → 496 tok/s`.
- **Decode падает с ростом контекста почти вдвое**: `48.8 → 40.0 → 23.2 tok/s` — цена attention
  по удлиняющемуся KV-кэшу (kvarn4, full-attention каждые 4 слоя).
- **MTP acceptance стабилен ~61–63 %** во всех трёх точках.
- Модель запущена с `--reasoning on` (`reasoning_effort=xhigh`): при `max_tokens=512` весь бюджет
  ушёл в reasoning-токены (`visible_tokens=0`) — на скорость генерации это не влияет (токен есть токен).

> Разброс между прогонами есть: decode tok/s зависит от MTP acceptance (варьирует по контенту,
> наблюдалось 46–65 %). Диапазоны по нескольким прогонам: 4K ~42–49, 32K ~32–41, 126K ~19–23 tok/s.

### Воспроизвести

```bash
python3 bench_speed.py --host 192.168.10.252 --port 8081 --json bench-results.json
# опции: --sizes 4096,32768,max   --max-tokens 512   --seed N
```

Требуется живой llama-server (`curl http://192.168.10.252:8081/health` → `{"status":"ok"}`).
